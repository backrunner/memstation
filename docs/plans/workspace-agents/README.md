本计划继承 [AGENTS.md](../../../AGENTS.md) 的工程、安全、视觉和 CI 基线。此次用户明确要求扩展工作区与多 Agent 范围；旧计划中“不扩写新的 v1 产品范围”不限制本次设计。组织、账单和分布式集群仍不是本次交付项。计划完成不代表功能完成，分阶段执行也不降低完整交付标准。

## 产品目标

同一个 MemStation 账号下，可以创建多个长期 Workspace，并授权多个 Agent 使用。Workspace 可以代表一个群、一个项目或一组个人事务。成员、会话、执行、记忆、证据和用量都有明确归属。

本次交付必须同时满足：

1. 群聊机器人在多个群工作，记录不触发回复的消息，按发言人构造有来源的画像。
2. 编码和审查 Agent 共用一个项目空间，保留各自执行记录，协作记忆不相互覆盖。
3. 个人 Agent 使用个人空间，按明确规则在其他空间使用可共享偏好。
4. 多个 Agent、多进程和重试请求同时使用同一服务，身份、事件和任务可追踪且可幂等。
5. 管理员能从记忆追到主体、源消息、执行结果、版本和授权原因，并完成修正、撤销与排障。
6. 现有个人用户和标准协议客户端迁移后继续工作。

## 核心决策

| 编号 | 决策 |
| --- | --- |
| D01 | `User` 保留为数据所有者；`Workspace` 是长期上下文及默认访问边界；`Agent` 是认证调用方；`Actor` 是发言和行动主体。 |
| D02 | Agent 与 Workspace 多对多授权。Agent 身份不随进程、模型、机器或 Run 改变。 |
| D03 | Workspace 与 Conversation 分离；Conversation 是有界处理窗口／线程，Run 是某个 Agent 的一次执行。 |
| D04 | 记忆的空间、描述主体、生产 Agent、可见范围和来源证据分别记录。 |
| D05 | 所有召回路径在取候选之前限制访问范围，图扩展、重排、证据、工具和缓存遵循同一策略。 |
| D06 | 同一人物跨群识别不自动共享记忆。跨空间共享通过可审计、可撤回的目标空间发布完成。 |
| D07 | 事件摄取与模型调用解耦；提供网关模式和独立记忆模式。 |
| D08 | 多 Agent 协作使用追加事件、来源去重、版本比较和候选冲突处理，禁止最后写入者直接覆盖事实。 |
| D09 | 记忆 generation 按 Workspace 管理；embedding 模型仍为部署级配置。 |
| D10 | Manager 区分服务实例 Target、工作区 Workspace、账号 User；不把三者塞成同一个选择器。 |
| D11 | Manager 业务数据由 SvelteKit server load／同源 API 获取，服务端保管目标会话；业务判断仍全部属于 Go 服务。 |
| D12 | 老账号迁入默认个人 Workspace；原有记忆不凭空推断群、人物或 Agent；旧凭据映射到兼容 Agent。 |
| D13 | 原有三种协议、REST、GraphQL Query/Mutation 和 gRPC 共同复用新业务上下文，不能只补 HTTP。 |
| D14 | 安全和正确性测试是阻塞门禁；记忆质量 benchmark 仍为本地／手动观察信号。 |
| D15 | 首次完整交付包括 Manager 全主流程、移动端、迁移与恢复演练；设计稿不计为产品实现。 |

## 典型使用流程

### 群聊机器人

管理员创建群 Workspace，绑定平台 Integration 和 Agent → 平台成员映射为 Actor → 机器人上报消息事件 → 服务完成去重、存储和异步记忆生成 → 需要回复时按触发消息构造本群上下文 → Manager 查看成员画像、原话和推断依据。

### 多 Agent 项目协作

管理员创建项目 Workspace，授权编码 Agent 和审查 Agent → 两者分别创建 Run → 上报工具执行和产物引用 → 共享已验证项目知识，保留私有执行笔记 → 相同事实的冲突进入候选审查 → 用量和失败按 Agent、Run 和 Workspace 定位。

### 个人与项目之间复用

个人空间保留用户偏好 → 管理员选择一条可复用记忆发布到项目空间 → 项目 Agent 只看到批准发布的内容 → 原始私聊和其他个人记忆不随之可见 → 发布记录可撤回，目标副本随来源撤回策略失效。

## 范围边界

| 本次必须实现 | 本次不扩展 |
| --- | --- |
| Workspace／Agent 生命周期、显式权限、Actor 和来源身份 | Organization／Tenant／Billing |
| 多人消息、外部执行事件、共享记忆、私有记忆 | 远程代码执行平台或 Agent 调度平台 |
| 并发写入、候选冲突、来源追踪、单空间重建 | 自动替用户批准身份合并或跨空间共享 |
| 全部现有 transport 的作用域一致性 | GraphQL Subscriptions |
| Manager、迁移、可观测性和可靠性验证 | 新向量数据库或第二套排序算法 |

Run 用于记录和关联外部执行，不声称服务能停止任意外部 Agent。平台连接器只需要通用协议、可运行接入样例和确定性测试适配器；具体第三方平台的账号配置、事件字段和授权流程在选择平台后单独核对官方文档。

## 完成判据

以下全部满足后才能将此次扩展标记为实现完成：迁移后的旧客户端通过协议回归；两个 Agent 可并发使用一个项目空间；同一机器人处理两个群而不串记忆；成员事实有准确主体及来源；撤权、编辑、撤回和冲突完整生效；管理员在桌面与移动端完成创建、接入、检索、修正和排障；HTTP／gRPC／GraphQL 权限一致；迁移、备份恢复和 Worker 恢复有机器可读结果。具体用例见 [实施与验收](delivery.md)。
