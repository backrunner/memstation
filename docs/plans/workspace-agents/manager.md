# 工作区与多 Agent 管理面板设计

Manager 的主要使用单位从“某个 User 的所有记录”调整为“当前 Workspace 的记忆与活动”。账号、服务实例、Agent 和后台队列仍各有明确位置。整体保留浅色、深绿品牌、IBM Plex Sans、紧凑表单和分隔线列表；不做新的装饰性控制台。

文档和设计稿以中文呈现流程，正式实现沿用现有 Manager 的统一产品语言规范；此次不隐含增加一套翻译基础设施。名称由用户输入，中文、英文和长名称都要通过布局验收。

正式组件以共享 token 提供浅色默认和暗色补充，两种主题都检查对比与状态可辨性。当前可点击设计稿仅展示默认浅色，不作为暗色主题验证证据。

## 1. 当前界面需要处理的问题

| 当前页面／实现 | 问题 | 调整 |
| --- | --- | --- |
| 顶部 Target 选择器 | 只表示后端地址，没有长期业务空间 | 服务连接与 Workspace 选择分开 |
| `Memory workspace` 标题／`Workspace` 子导航 | 指用户记忆总览，和新实体同名 | 改为“记忆”；真正 Workspace 成为全局上下文 |
| `Users` 同时承载 key、模型和重建 | 群成员、账号所有者和调用 Agent 容易混淆 | Users 保留账号管理，成员放空间内，凭据迁到 Agent |
| `Agent Memory` 子页 | 目前代表通用事件、任务等记忆类型 | 改为“事件与知识”，避免误以为 Agent 私有记忆 |
| `user_id` query 与零散 page load | 新增空间后易漏传范围或展示旧响应 | 统一 ScopeContext、路由和请求生命周期 |
| Conversation detail | 只凭 role 难区分多人及多 Agent | 人物／Agent 标识、Run、引用和消息版本 |
| entity_scope 文本框 | 看起来像授权空间 | 移入高级“名称消歧范围”，明确不改变 Workspace |

既有历史 Fact 筛选、关系方向、来源证据、别名确认、版本链、Playground、运维和多 Target 能力全部保留。

## 2. 信息架构

桌面侧栏固定两组导航；当前 Workspace 的日常工作在前，全局管理在后。只显示当前能力支持的项目。

```text
MemStation                         服务连接：Local
工作区选择：MemStation 项目 ▾

当前工作区                         管理
  概览                              工作区
  记忆                              Agents
  对话                              接入来源
  执行记录                          运维 ▾
  成员与实体                        系统设置 ▾
  设置与访问

检索调试／协议调试放在当前工作区工具入口；
账号用户在系统设置中，单用户不占用一级日常导航。
```

服务连接位于侧栏底部／桌面顶部次要区域；Workspace picker 位于导航上部并持续可见。移动顶部保留菜单、当前空间和页面名，服务连接放进导航抽屉。只有一个空间时显示名称而不展示无意义下拉；创建和管理入口仍可在管理页面找到。

全局工作区列表可筛选 owner；进入空间后标题显示该空间名，账号只在必要时作为次要元信息。Agent 注册列表是全局入口，空间设置中的“可访问 Agents”是同一资源的筛选视图，不创建第二套授权配置。

## 3. 路由和作用域状态

建议新路由统一为：

| 路由 | 页面 |
| --- | --- |
| `/t/:target/workspaces` | 工作区目录和创建 |
| `/t/:target/w/:workspace/overview` | 空间概览 |
| `/t/:target/w/:workspace/memory` | 统一记忆检索／浏览 |
| `/t/:target/w/:workspace/memory/:kind/:id` | 记忆详情、编辑、来源与历史 |
| `/t/:target/w/:workspace/conversations[/:id]` | 对话及多人时间线 |
| `/t/:target/w/:workspace/runs[/:id]` | 外部 Agent 执行记录 |
| `/t/:target/w/:workspace/subjects[/:id]` | 成员与实体及画像 |
| `/t/:target/w/:workspace/access` | 访问授权与共享发布 |
| `/t/:target/w/:workspace/settings` | 空间设置、归档与重建 |
| `/t/:target/agents[/:id]` | Agent 注册、凭据和跨空间授权 |
| `/t/:target/integrations[/:id]` | 来源绑定、身份命名空间与摄取状态 |
| `/t/:target/operations/*` | 健康、Worker 队列／任务、缓存、审计和用量 |
| `/t/:target/w/:workspace/playground/*` | Chat、Recall、Protocols |

URL 决定目标与空间；用户最近选择只负责没有明确 URL 时的默认值，不能覆盖深链接。过滤、类型、搜索词、主体、排序、游标和选中详情应能恢复；敏感搜索文本不写遥测。旧路径通过服务端解析 legacy owner/default workspace 后重定向，保留可识别的筛选；无法解析时显示工作区选择，不默认归到 admin。

切换空间行为：

1. 无编辑时立即切换，保留页面类别及通用筛选，清除旧对象、旧 cursor 和不适用主体。
2. 有草稿时提供“保留草稿并切换／继续编辑”，草稿键包含 target/user/workspace/resource/revision；不保存密钥。
3. 请求取消并递增作用域版本，晚到响应不能覆盖新空间；切换后立即清空旧详情和旧权限。
4. 跨空间切换不沿用旧 Conversation／Run；浏览器前进后退恢复正确作用域和列表位置。
5. Target 切换另外验证该 Target session；同名 Workspace 不代表同一个对象。

## 4. 关键页面和交互

### 4.1 工作区目录和创建

目录采用搜索＋列表，展示名称、类型、简短说明、最近活动、待处理数量。创建只要求名称和类型；项目仓库／群平台绑定作为可选第二步，授权 Agent 可在创建后添加。默认不复制其他空间记忆。

创建成功进入新空间概览，空态给一个主要动作“接入 Agent”，并提供查看接入示例的文字链接。归档空间明确显示只读原因和恢复入口；删除须展示会受影响的源数据、记忆、发布项和执行记录，随后进入可追踪清除任务。

### 4.2 空间概览

使用紧凑数字行展示记录、记忆、最近执行和处理积压，数字可跳转对应筛选列表。主体是最近活动和需要处理的异常，如冲突候选、来源修订、摄取失败。没有异常不展示重复“正常”状态卡。数据时间标记说明统计窗口和刷新时间。

项目空间优先显示执行与产物；群空间优先显示最近对话、活跃成员与待确认画像；个人空间优先显示近期记忆和待办。差异来自同一组件中的内容优先级，不维护三套独立页面。

### 4.3 记忆列表和详情

搜索栏与结果优先。类型过滤保留全部／事实／印象／摘要／关键记忆／事件与知识；主体、生产 Agent、可见范围、时间、历史查询和代码适用条件放进可展开筛选，保留选择并显示已选摘要。

普通行展示正文、描述主体、类型、来源时间和可见范围；当前空间固定时不重复每行显示空间名。生产者、分数和技术 ID 放次要元信息。异常行以文字和轻填色提示“冲突”“来源已撤回”“待确认”，不为每个正常状态使用胶囊。

桌面宽屏点击正文进入可链接的详情侧栏，保留列表；窄屏使用独立详情页面，返回恢复筛选和滚动位置。交互不是只能点击整行，正文链接和操作按钮有明确键盘焦点。

详情顺序固定为：

1. 正文和描述主体，主要操作“编辑”。
2. 可见范围与适用条件；改变可见范围独立提交，显示目标受众，不随普通文字编辑偷偷改变。
3. 来源证据：发言人、源消息时间、直接引用／转述／推断、工具真实结果；可跳回消息与 Run。
4. 修订与冲突：当前版本、候选版本和证据差异；显示保存冲突而非覆盖草稿。
5. 关系与原始数据按需展开。关系有可读名称和真实详情链接，不只显示 UUID 或装饰图。

编辑使用 expected revision。遇到 409 显示当前正文与用户草稿，允许合并后重试、重新载入或保留草稿；不在后台自动 overwrite。来源被删时明确显示“来源已撤回／已按保留策略清理”，不要伪造原文链接。

### 4.4 成员与实体画像

默认分为“成员”和“实体”两类列表；Actor 的账号 ID、昵称与外部身份可在详情查看。同名成员并列显示来源标识，不自动合并。代码资源展示仓库、文件或符号的可读名称。

成员详情首屏展示本空间内的已确认事实、印象和近期发言。事实与推断分区；每条画像可展开证据。跨空间身份绑定不会直接展示其他空间画像。管理员需要跨空间检查时，显式选择目标空间并重新加载；Agent 模拟视图不提供管理越权内容。

身份合并入口先展示两边来源和冲突，支持候选／确认／撤销；不得因昵称相同直接执行。用户修正画像必须保留原判断、理由及审计记录。

### 4.5 Agent 目录、详情和授权

列表展示名称、用途、授权空间数、最近活动、失败情况；“最近活动”不等同在线状态。详情分为“概览／访问范围／凭据／执行与用量”，默认先看到用途和最近执行。

授权表按 Workspace 为行、能力为列；常用只读／记录／协作模板是权限组合的快捷选择，保存后仍展示实际能力。默认不勾选所有空间或未来新空间。已有权限受 credential 上限限制时显示实际有效权限及来源。

保存前用精简差异区展示新增／移除的空间和能力；撤销会立即影响后续请求，已接受的后台处理语义按架构文档执行。Agent 停用不等于删除历史记忆。

新凭据创建流程：选择 Agent → 默认空间和权限上限 → 一次显示明文 → 可复制示例。关闭后只能看到 prefix、创建时间、最后使用和撤销操作；刷新不能找回完整 key。凭据不进入 URL、storage、截图 fixture 或表单草稿。

### 4.6 对话与执行记录

Conversation 时间线每条显示发言人、角色、时间和引用。多个 Agent 的回复区分 Agent 名称与 Run 链接；工具调用与真实返回成对显示，错误和未完成调用可定位。历史编辑显示版本标记，默认读当前可用版本。

Run 页面显示目标、调用 Agent、状态报告时间、父子执行、工具步骤、产物、消耗和产生／使用的记忆。默认列表按最近活动排序；支持 Agent、会话、状态和时间筛选。消息内容与原始 payload 按需展开。

Run 与 Worker Task 必须分别命名为“执行记录”和“后台任务”。没有远端控制能力时不显示“停止 Agent”按钮；可以“结束记录”，并明确其不终止外部进程。失败 Run 的重试只在连接器实际支持时提供，否则给接入方可复制的诊断信息。

### 4.7 接入来源

Integration 详情显示平台／连接器、身份命名空间、群或仓库到 Workspace 的映射、最后摄取时间、accepted/indexed watermark 和失败事件。重复事件显示计数，用户可区分“已收到”与“记忆处理完成”。

接入向导提供 Gateway／独立记忆两种示例，并使用选定 Workspace 和 Agent。代码示例使用配置模型名和占位 key；能复制，不能把已有凭据完整自动嵌入。具体平台配置只在该连接器实现后显示，不把通用示例宣称为已验证平台集成。

### 4.8 共享发布与冲突处理

发布入口位于记忆详情和空间访问页。弹窗展示来源、待发布正文、目标 Workspace 与受众；默认仅共享正文，不附带原始会话。确认后显示目标记录链接和同步状态。撤回发布能定位受影响目标记录。

冲突候选列表展示主体、事实键、现值、候选值和证据。操作为接受新版本、保留现值、保留并列条件或拒绝；“保留并列条件”要求填写可区分的适用条件，不能靠无意义复制掩盖冲突。批量操作只适用于同类、同空间、同权限对象，返回逐项结果。

### 4.9 调试、设置和运维

Recall 调试显式选择 Workspace、模拟 Agent、输出受众和查询；结果展示来源、分数及可见的排除原因。管理员全量检查与模拟 Agent 模式标签区分清楚。Chat／Protocols 默认 memory persist 与写工具关闭；开启前选择写入空间，不能不知不觉污染生产记忆。

设置展示有效值及继承来源：系统／用户／空间／Agent。权限不是覆盖链，而是能力交集。Embedding 模型只有部署级入口，不在每个 Agent 或空间提供可编辑模型字段。

Queues／Tasks 增加 Workspace／Agent／Run 关联和筛选；全局健康保留实例维度。Usage 支持空间和 Agent 分组，并分开实际 Gateway、后台分析和外部自报。重建入口移到 Workspace 设置，显示快照 watermark、增量追平、验证、激活和失败原因。

## 6. 状态、响应式和可访问性

| 状态 | 必须呈现的行为 |
| --- | --- |
| 初次加载 | 保留页面标题／范围，骨架只占列表区域 |
| 空空间 | 说明下一步接入动作，不展示虚构统计 |
| 无搜索结果 | 保留关键词和筛选，提供清除筛选／重试 |
| 只读／无能力 | 隐藏不可用主要动作，必要处解释原因；服务端仍校验 |
| 401 | 重新连接该 Target，保留非敏感草稿和返回路径 |
| 403／404 | 清理不可见旧对象，不在缓存中继续显示 |
| 409 | 保留草稿，显示版本比较和明确处理动作 |
| 429 | 显示重试时间，禁用重复提交，查询保留 |
| 异步处理中 | 显示实际阶段和更新时间，支持稍后返回 |
| Target 失联 | 展示连接错误和重试，不把旧结果标为当前 |

屏幕验收覆盖 320、390、768、1280、1440px，以及短屏、200% 缩放、键盘和触屏。移动主要操作至少 44px，输入文字至少 16px。对话框按可视视口限制高度并可滚动，底部保存区不盖住最后字段；软键盘弹出后主操作仍可达。

表格在窄屏转换为带明确标签的记录行；Agent 权限表转换为每个 Workspace 一组能力开关，避免横向大表格。二级栏目允许横向滚动但必须露出当前项。普通状态只用文字；颜色不能是唯一区分信号。

使用共享表单标签／帮助／错误描述，Dialog 有焦点约束与关闭后恢复，菜单有键盘导航。筛选展开、加载、结果数和保存结果通过适当 aria 状态反馈；不为每次轮询播报整页。

## 7. 前端实现边界

复用 PageHeader、FilterToolbar、TextInputField、SelectField、ConfirmActionDialog、FactLineagePanel、EntityAliasPanel、ChatMessageCard、JsonView；按新增 DTO 改造而非复制出多套组件。

新增模块建议：

```text
src/lib/scope/                 # 统一 Target/Workspace/owner 上下文、URL 与请求代次
src/lib/server/targets/        # 目标登记、服务器会话保管、薄传输
src/lib/server/api/            # typed Go API 客户端
src/lib/components/WorkspacePicker.svelte
src/lib/components/ScopeHeader.svelte
src/lib/components/AgentGrantEditor.svelte
src/lib/components/MemoryEvidencePanel.svelte
src/lib/components/RevisionConflictDialog.svelte
src/lib/components/RunTimeline.svelte
src/routes/t/[target]/...      # server load、同源 actions/API、页面
```

`src/lib/memory/workspace.ts` 的旧命名改为 memory-browser／query，不与真正 Workspace domain 混用。表单草稿和请求缓存使用统一 scope key，取消重复的各页面临时 user_id fallback。GraphQL／REST／gRPC 的 DTO 来源和字段在 contracts 文档统一。

后台状态默认使用有界轮询，页面隐藏暂停、失败退避、卸载取消；不新增 GraphQL subscriptions。原生 Svelte 实现保留现有版本，不为设计稿引入框架依赖；任何必要依赖升级实施时核对稳定版本并附回归说明。

## 8. UI 完成标准

管理员应能在桌面和手机完成：创建工作区、接入两个 Agent、发放与撤销凭据、看有效权限、按主体检索、追到源消息、编辑冲突处理、发布与撤回共享记忆、查看并发 Run、区分后台失败、归档空间。所有路径均要有真实服务 E2E；设计稿和 fixture 只证明交互与布局，不替代真实鉴权和数据库验证。
