# Mixed memory regression

This manual suite combines historical LOCOMO/LongMemEval wrong answers with MemoryArena wrong answers and output-budget failures, plus successful controls. It is a fixed development diagnostic, not held out or representative. Raw data and the generated selection must remain outside version control.

`prepare-memory-regression.py` consumes explicit historical result paths and original datasets, pins every input hash, reserves failed LOCOMO capability groups before filling eight failures and two controls, retains all LongMemEval failures plus answerable/abstention controls, and chooses three shortest complete Arena chains per domain: execution failure, wrong answer without execution failure, and full success. Ties use a fixed seed/ID hash. Freeze this selection before new model calls. Never remove a regression or failure from its denominator after running.

The initial cohort has 35 questions and 140 result records across `none`, `raw`, `derived` and `combined`. The 18 Arena `none` records are reused from the completed low model-only control; they are not new generation/judge calls. Arena chains execute chronologically and independently per arm. Own completed answers and their observed current public setup are remembered regardless of grade; partial answers, references, judge feedback, future questions and future backgrounds are never ingested. LOCOMO source event annotations and LongMemEval `has_answer`, answer-session and question-type labels are excluded from worker and retrieval inputs. All original history sessions are ingested, not only annotated evidence.

`TestLiveMemoryRegression` is skipped by default. Set `MEMSTATION_EVAL_REGRESSION_PLAN`, a fresh `MEMSTATION_EVAL_REGRESSION_OUT`, `MEMSTATION_EVAL_CODE_REVISION`, and a dedicated loopback `MEMSTATION_EVAL_DATABASE_URL` whose database starts with `memstation_eval_`. Apply current migrations to an empty database. Configure ANSWERER/EXTRACTION/JUDGE model, endpoint, key and explicit zero temperature; pin embedding/rerank model revisions. Use a private content-only embedding cache. Memory arms have no answer cache or selected-case retry. Arena model-only controls require pinned `arena_baseline_manifest` and `arena_baselines` sources, including original wrong answers and execution failures. Missing controls or a mismatched model fail before worker/provider work. The plan preparation script supplies these from the existing complete Arena run. Changing the baseline model requires a separate explicit experiment, never an automatic refresh.

The suite uses actual PostgreSQL repositories, conversation finalization, outbox relay and production worker handlers through one persistent run-wide local task queue with bounded worker concurrency. It verifies Summary/Analysis completion and persists their Fact and other memory nodes plus embeddings. The dispatcher starts with no request principal; each production handler validates its persisted task authority and binds the exact envelope scope. Concurrent producers never drain global outbox work under one request owner. This exercises worker business processing, not Redis/HTTP scheduling transport. `raw` retains original records; `derived` retrieves worker outputs; `combined` additionally admits segments and bounded original source windows. The original transcript is never rewritten to match a reference.

Initial reader/worker budget is 16K, one explicit-truncation retry at the configured 64K ceiling; a ten-minute evaluation deadline accommodates reasoning. LOCOMO/LongMemEval readers retain high thinking, Arena retains low, extraction uses low. These settings apply to newly executed memory arms and static controls. Reused Arena controls retain their historical prompt and 8K-to-16K token policy; report that difference explicitly and do not describe their comparison as a same-budget causal ablation. Their historical usage is excluded from current reader/judge spending. Prior full-benchmark scores remain separate.

Retrieval records include scope/keyword/vector/graph/hydration/rerank/ranking times, actual cross-encoder input bytes, full ranked results, evidence-packing time and source availability. Direct keyword/vector recall runs concurrently; their wall times overlap and must not be added. Local cross-encoder requests are serialized outside the provider deadline, with queue time included in search latency. Compare short worker records with original long-session records before changing deployment defaults; fewer candidates and smaller models can affect recall and require separate quality checks.

Do not claim an online SLO pass, cold-path speedup from a warm cache, independent judging, or SOTA from this cohort. Report every execution failure, type of worker task, actual persisted summaries/facts, latency phase and paired gain/regression.

Source-grounding validation covers every fact, impression, item and episode before checkpoint persistence. One model-only correction is allowed using the same original input and a trusted fixed hint; rejected claims never become evidence, consume accepted limits or enter storage. Validated batch checkpoints are revalidated against their exact source batch. Sources explicitly identify which user/tool IDs can support evidence, while assistant text remains available as context. Summary fields and scores use the same bounded correction boundary. An exhausted task remains failed and recorded; its owner's ingestion fails without poisoning another owner's pending work.

All context arms preserve whitelisted source dates through the production formatter. Post-retrieval annotation overlap is reported separately before and after packing. For derived paraphrases this is source provenance coverage, not proof of semantic completeness. Annotations never enter the prompts or influence selection.

Performance ablations must be preregistered across all static cohort questions and run only after worker ingestion completes. Use a SELECT-only role for the same fixed worker corpus, preserve the original source arm, and record model revision, candidate limit, context, new baseline QA, phase latency and all failures. Arena must not be replayed against its final database for earlier steps: that would expose future experiences. Warm sequential measurements are separate from the queue-inclusive primary run. No model or candidate limit is promoted automatically.

Run the primary with `bash scripts/eval/run-memory-regression.sh` after setting the frozen plan, fresh private output, dedicated migrated database, pinned model revisions, role endpoints and credentials. Its summary retains all 140 planned answers even when a process or provider fails. Do not point it at an application database.

For a separate static profile, prepare a private plan containing `parent_plan_sha256`, every static `[dataset, question_id]` pair, `modes` (`raw`, `derived`, `combined`), `qa_modes` (`derived`, `combined`), and fixed variants (`name`, model reference, weight revision, maximum candidates, and optional `top_n`; omitted `top_n` uses the parent limit). Set `MEMSTATION_EVAL_REGRESSION_PROFILE`, `MEMSTATION_EVAL_REGRESSION_PLAN`, `MEMSTATION_EVAL_REGRESSION_PARENT`, a fresh `MEMSTATION_EVAL_REGRESSION_PROFILE_OUT`, a SELECT-only `MEMSTATION_EVAL_DATABASE_URL`, pinned role/model configuration and `MEMSTATION_EVAL_SMALL_RERANK_BASE_URL`; run `bash scripts/eval/run-memory-profile.sh`. Primary ingestion failures stay failed in every corresponding profile arm, preserving the full denominator. Hash the corpus before and after profiling to confirm it did not change. Reports are written beside each private run.

An additional full-original LOCOMO diagnostic can isolate reader/input limitations. Set a fresh `MEMSTATION_EVAL_REGRESSION_FULL_SOURCE_OUT` and run `TestLiveRegressionFullSourceRead` explicitly with the same frozen cohort, code revision and role configuration. It reads every selected LOCOMO question and all of that conversation's human turns, rendering the original session date once and preserving every speaker/utterance. It uses the primary input ceiling, prompt, reasoning and output budget. An oversized complete transcript is an explicit failure, never truncated to a favorable window. Keep its independent denominator and report separate from retrieval results; full source does not prove a theoretical upper bound or eliminate judge ambiguity and missing modalities.

A development TopN ablation can test broader evidence admission within the same context ceiling. Use the complete fixed static selection and a new baseline control, record that first-stage prefetch may also change, and keep every regression. Register it before profile calls; if motivated by observed primary failures, describe it as development tuning rather than independent validation. Never promote one case's full-source answer into another arm.

The primary cohort is explicitly **human text only**. This is narrower than caption-inclusive LOCOMO inputs: the official dataset supplies image URLs, BLIP captions and image retrieval queries separately from QA annotations, and Mem0's [public ingestion adapter](https://github.com/mem0ai/memory-benchmarks/blob/main/benchmarks/locomo/run.py) includes the caption/query. For the separate full-source reader diagnostic, `MEMSTATION_EVAL_REGRESSION_PROVIDED_IMAGES=true` includes those provided observations with an explicit generated-image-metadata label. Use another fresh output directory and the same ten questions, reader and judge. It never includes event summaries, generated memory annotations or QA labels. Report this input-policy change separately; do not compare the human-only score directly with caption-inclusive benchmark claims, substitute its answers into the primary, or call supplied descriptions verified visual facts. This diagnostic does not rebuild worker memories from images or measure production vision extraction.

Native production media routing is documented in [Native media input](../../../../docs/multimodal-input.md). The original frozen transcript-only diagnostic is not retroactively relabelled a vision benchmark. Media-enabled evaluations need a new source-policy manifest and must keep reference answers/event annotations out of ingestion. Automatic profiling and reader probes require an explicit bounded run; they are not a consequence of completing this suite.
