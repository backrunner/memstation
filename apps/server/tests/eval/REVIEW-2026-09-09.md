# Graph memory and evaluation review — 2026-09-09

The current benchmark remains LOCOMO-first, with separate retrieval and answer-quality tracks. There is no single universal memory benchmark: conversation recall, long-horizon question answering, and learning from agent trajectories measure different capabilities. A high retrieval score alone is not evidence of good final answers or reliable memory construction.

## Defects corrected

- Generation inference previously chose one endpoint, with map iteration determining the in-memory result and database errors ignored on PostgreSQL. Both endpoints now participate in resolution; conflicting generations and cross-user database endpoints are rejected. Scoped reads also reject conflicting legacy endpoints.
- The pending relation migration previously deleted unresolved or conflicting edges. It now backfills only unambiguous relationships, handles a generationless Key Memory on either endpoint, and retains other historical edges for inspection/rebuild. The migration is idempotent and was tested on an isolated PostgreSQL 16.14 database.
- Semantic neighbourhood expansion is bidirectional and bounded. It does not amplify paths, propagate zero-weight links, or use contradiction/supersession history as a positive graph boost. These are implementation choices to assess with ablation, not benchmark-mandated constants.
- LOCOMO previously split speakers into different principals and indexed both annotated event summaries and upstream-generated memory. The raw-dialogue track now shares one principal per conversation sample and indexes dialogue turns with speaker/date context. Name/date metadata leaves are not indexed as standalone facts.
- LongMemEval turn documents no longer carry gold `has_answer` or question-type labels into the memory store. These annotations are used only to construct evaluation judgments.
- Duplicate retrieval rows no longer inflate recall, nDCG, or relation hit rates. Duplicate ranks remain occupied; truncated results cannot shrink the ideal nDCG denominator. Relevance judgments must be finite and consistent with positive IDs. Ownerless results count as isolation leaks.
- LongMemEval QA validates all reference/hypothesis IDs before any judge requests. Reports include reference count, coverage, and missing hypothesis IDs; accuracy remains the official-style score over evaluated questions and must be interpreted with coverage.
- The repo-native smoke test still enforced ranking thresholds inside ordinary `go test`. Full benchmark tests are now opt-in, and hard thresholds require `MEMSTATION_ENFORCE_BENCHMARKS=true`. Correctness tests for parsers, scoring, isolation, and runner behaviour remain enabled.

## Validation and interpretation

- Full server `go test ./...` passed, including PostgreSQL relation generation/isolation and migration retention/idempotency tests on an isolated database. All SQL migrations replayed successfully; the Atlas directory checksum was regenerated using Atlas's own library.
- Repo-native deterministic smoke exported 20 queries across four ranking variants. The official LOCOMO raw-dialogue adapter exported 1,532 evidence-backed queries across the same variants. These runs verify executable paths and artifacts, not embedding quality. LOCOMO questions without usable dialogue evidence and the configured category-5 exclusions are outside this retrieval track.
- The deterministic native run showed zero wrong-user and stale-top-k exposure, but no positive relation expansion gain. This does not establish a quality improvement from graph ranking. Inspect per-query failures and repeat with provider embeddings before drawing ranking conclusions.
- No provider-backed accuracy result, paid QA judge run, production-scale latency claim, or LongMemEval-V2 result is claimed. External quality runs require fixed model versions, dataset revisions, retrieval/reader budgets, full coverage, per-category results, and latency/cost reporting. V2 additionally requires its official trajectory/reader contract; importing its data as V1 conversations would be invalid.
- The existing `golangci-lint` v1.64.8 could not read current Go export data. The lint entrypoint now pins the verified stable v2.13.2 release and uses the official v1→v2 configuration migration, preserving the enabled correctness linters and legacy exclusions. `gosimple` is included in v2's `staticcheck`. Equivalent report-formatting and boolean-expression fixes satisfy the additional suggestions; lint reports zero issues.

Local diagnostics are in `.artifacts/eval/smoke/`, `.artifacts/eval/locomo/`, `.artifacts/server-tests-final.log`, and `.artifacts/server-lint-v2.log`. Original external data remains outside version control. No migration was applied to an existing user database.
